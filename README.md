# 纸上飞驰 · Paperlap

方格本上的 2D 玩具赛车。画一条首尾相连的路线，用键盘自己驾驶，完成一圈并挑战本地纪录。默认赛道打开即可玩，全部游戏逻辑在本地运行，无后端、无 AI 调用、无外部字体或资源请求。

![游戏画面](docs/screenshots/final-game.png)

## 本地运行

需要 Node.js **22.12+**（开发验证使用 22.22.3）、npm 和现代桌面浏览器。

```bash
npm ci
npm run dev
```

打开终端显示的地址，默认是 **http://127.0.0.1:5173/**。服务不会自动启动浏览器。

```bash
npm run typecheck
npm test
npm run build
npm run preview
```

构建输出在 `dist/`；生产预览默认地址为 http://127.0.0.1:4173/。Phaser 引擎随包一起发布，首屏无需远程下载素材。Vite 可能提示引擎 chunk 超过 500 kB，这不影响构建或运行。

## 怎么玩

- 游戏区域获得焦点时按 **Space** 或点击“开始试跑”，按住 **↑ / W** 加速，**↓ / S** 刹车，**← / A**、**→ / D** 转向。没有倒车，静止时不原地旋转。
- **Space** 保留快速开始/暂停/继续。**Esc** 或顶部“菜单”打开正式游戏菜单，立即冻结车辆、计时和引擎；提供继续、重新开始、赛道本、编辑当前、声音与操作说明。离开窗口、切换标签或游戏区域失去焦点时自动暂停，松开所有按键。
- 只有菜单直接从驾驶中打开、仍是原赛道且期间没有失焦/隐藏/缩放或进入赛道本/编辑，Esc 关闭才可恢复驾驶。ready、已有暂停或恢复条件失效时，关闭保持原状态，需显式开始/继续。恢复会清键，原来按住的油门必须松开重按。
- 游戏区域按 **R** 或“重新开始”回到起点并开始新一圈，保留最快成绩；ready、running、paused 均可用。
- 左上纸片以“当前赛道：名称”为主标题，长名称截断显示，鼠标悬停可查看全文，键盘也能聚焦名称。“自由试跑”为次要模式信息；右上书本图标 +“赛道本”+ **T** 打开右侧纸片抽屉，显示真实路线缩略图、个人最佳与当前标记。名称最多 40 个字符，允许重名。
- 游戏区域按 **E** 或点击“编辑当前”进入画线模式，顶部持续显示“编辑当前赛道”、目标名称和替换说明。在虚线范围内按住鼠标左键画一个大圈，回到起点圆圈内松开即可自动闭合、整理手抖和接头。圆圈变绿、显示“已回到起点”时就可以松开，不必精确接上第一笔。
- 抽屉按 **N** 新建，按 **↑ / ↓** 在卡片主按钮间移动焦点，按 **Enter / Space** 使用赛道；Tab 可访问改名、删除。改名/删除确认中 **Esc** 先回列表，列表中 **Esc** 关闭并回到入口，关闭不会自动恢复驾驶。从菜单进入时返回菜单；直接按 T 进入时返回游戏。
- 新建时显示“新建赛道”，通过“保存新赛道”或 Enter 保存为独立条目，原有赛道保留，再点击“开始试跑”出发。编辑当前时通过“保存修改并试跑”或 Enter 替换当前条目的路线并起跑。切换赛道会回到起点、清空本圈并等待开始，删除需要明确确认，最后一条不能删除。
- 两种绘图模式均可按 **R** 清空重画，按 **Ctrl/Cmd+Z** 撤销整次笔迹或清空，按 **Ctrl/Cmd+Shift+Z** 重做，顶部按钮显示本机键帽和可用状态。无笔迹时按 **Esc** 取消；已有笔迹、预览或可撤销内容时先显示“继续绘制 / 放弃修改”，默认继续绘制。只有显式放弃才清理对应草稿并恢复原赛道、车辆位置和计时；已确认备份的清理失败会保留编辑状态；若从一开始就无法确认备份，可在明确告知旧备份不会删除后“仅放弃本次绘制”并返回。取消回原编辑入口，不改正式赛道。绘图提示位于画布顶部和底部；准备/暂停操作位于底部纸条，成功与新纪录反馈位于右上边缘。实际快捷键均以“图标 + 中文动作 + 键帽”显示；输入框、IME、Ctrl/Meta/Alt 和按钮原有的 Enter/Space 操作保留，动作键忽略长按重复，编辑器撤销/重做仅处理专用组合键，不拦截输入框原生撤销。
- 开放线、交叉、过短、确实容不下道路的尖弯、道路挤在一起或太靠纸边仍会提示原因。无效草稿不能起跑或覆盖存档。拖画时失焦、改变窗口大小或丢失鼠标捕获会中断当前笔迹，可以直接重新按住鼠标画一圈。
- 出界会明显减速，并使本圈不计成绩。仍能开回道路，按顺序经过整圈检查点、正向跨起点线后开启新的有效圈。想立刻重试可以按 **R**。
- 上方显示本圈与个人最佳。只有有效圈刷新纪录。底部“声音”按钮可开启声音或静音，初始为静音；音效启用失败不影响游戏。

![真实路线卡片与快捷键](docs/screenshots/p1-03-drawer-1366.png)

菜单与抽屉采用有层次的纸片落位，退出更快；编辑/新建通过独立纸页交接，触笔立即收走旧页。按钮按下/释放、键盘铅笔标记、卡片选中与纪录印章各有明确反馈。真实状态和焦点立即更新，不等待动效；选择/保存成功后才庆祝。系统“减少动态效果”首次生效或运行中改变时立即收敛。统一节奏和完整操作盘点见 [Motion Spec](docs/game-motion.md)。当前 Esc 菜单、草稿确认与返回链见 [游戏菜单规则](docs/game-menu.md)，赛道本细节见 [交互规则](docs/trackbook-interactions.md)。

## 正式游戏局部调整

按 **L** 或点击“局部调整”，也可从 Esc 菜单或赛道本进入。只编辑当前已保存且可写的 V3 赛道；**E 仍是整圈重画**，两者独立。进入时赛车、圈时、声音与驾驶按键冻结，原路线用虚线对照，黄色显示本次影响区，灰色起点区不能拖动。

在道路上按住鼠标拖动，松手后检查合法性。**Enter / 采用本次调整**只加入编辑历史，可以继续改另一个弯；**Ctrl / Cmd+Enter / 保存局部修改**才正式写盘。保存成功保持作品 UID、名称和历史纪录，为新几何建立独立成绩身份，并回到等待开始。非法预览、未采用预览、存储或场景失败都不会冒充保存成功。

**Ctrl / Cmd+Z** 撤销，**Ctrl / Cmd+Shift+Z** 重做，会话内最多 24 次。**Esc** 先取消当前拖动/预览，再确认是否放弃已采用修改；默认继续调整，取消沿游戏/菜单/赛道本原路返回且不自动驾驶。失焦、切换标签、resize 或指针中断只取消未采用部分，不覆盖上一次合法草稿。

采用、撤销或重做后备份到独立 `paperlap.local-draft.v1`，不混用整笔草稿。刷新后重新进入 L，匹配同一作品/几何修订/算法时提供“继续局部调整 / 放弃草稿 / 暂不处理”，不会自动覆盖正式赛道。刷新恢复最近一步撤销/重做；草稿最多 8 份 / 1,200,000 字符，不自动淘汰。初读失败时明确提示未备份，可确认仅放弃内存；已确认备份清理失败则留在编辑器。旧修订或其他作品的草稿保留原文，不自动套用。全部存档备份也包含局部草稿。

[状态与失败恢复合同](docs/local-editor-integration.md) · [测试、性能、截图和真实录屏](docs/local-editor-verification.md)。不提供自由贝塞尔手柄或云同步。

## 存档

正式存档使用当前 origin 的 **`paperlap.save.v3`**。每条作品保留 UID、名称、中心线和声音偏好；几何修订另有独立 `geometryIdentity` 与版本化 SHA-256 摘要。个人最佳绑定 UID＋修订身份＋规则版本，即使细微改线仍碰巧得到相同旧指纹，也不会继承错误成绩。改名、切换、静音和原几何重复保存保留身份，新建与真正改线获得新身份。最多 20 条赛道。

首次升级完整读取合法 V2，或沿既有规则读取 V1；只有新 V3 完整验证、可靠写入并读回成功后才启用。**V1/V2 原始键永远保留，不双写、不自动删除。** 所有可读旧 records 与孤立归档完整转入历史，不成为新身份的权威 PB。HUD 和赛道卡片会标明“旧纪录（未验证）”；点击 HUD 的历史入口可逐项查看不同规则、历史几何和孤立成绩，并导出包含全部正式键、旧/新整笔草稿和局部草稿的备份。V1 的过长名称、会被旧解析器过滤的纪录或不支持的字段会拒绝升级，不静默裁剪；原文可导出。

新建、切换、改名、删除及整圈保存通过候选→场景准备→可靠写入→场景提交。保存失败保留旧正式状态、候选和草稿；V3 整圈替换也不再将失败当成临时保存成功。成绩写入失败不更新正式 PB。场景提交异常会停止操作并要求重新加载。

同一 origin 采用 **单写入标签**：持有 Web Lock 的标签可以保存，其他标签只读，关闭写入标签后刷新重试。无 Web Locks 的浏览器仅只读试玩。旧客户端改动 V1/V2、新版外部改动 V3、损坏/未知 V3 或摘要不匹配均停止写入，原文保留；错误状态在 HUD 持续可见。刷新不会合并冲突分支。升级配额失败可释放空间后刷新重试，迁入身份稳定不变。

整笔草稿在 V3 会话使用独立 **`paperlap.draft.v2`**，绑定 UID＋几何身份＋摘要＋新建/编辑意图；原 `paperlap.draft.v1` 保留，只读提示，不凭旧指纹自动套用。撤销/重做仍以整笔为单位，最多 24 层；完成、中断、历史操作立即备份，绘制中最多每秒一次。未完成的新笔保留上一份完整稿，刷新恢复后可撤销找回。最多 12 份 / 600,000 字符，不自动淘汰。正式保存且场景成功或明确放弃后才清理；已确认备份清理失败继续编辑，初读失败允许明确确认后仅放弃内存稿。来源无法验证或只读时不会写新草稿，界面明确提示未备份。

恢复或回滚前先从历史面板导出全部键，关闭其他标签，并保留导出文件。回滚旧版只会看到保留的 V2/V1，不包含 V3 新作品；再次回新版可能因旧键变化进入冲突保护。此阶段不自动合并或提供一键删除损坏 V3。源冲突不能靠刷新消除时，需恢复一份所有键相互一致的可信备份；没有一致备份时请保留两份分支继续只读核对，不要自行改摘要来强行覆盖。

端口、域名或浏览器不同会有独立存档。保留旧键会占用额外空间；配额、历史容量或结构不支持时整体拒绝，不裁剪数据。协议、限额、故障矩阵和兼容取舍见 [Save V3 RFC](docs/save-v3-rfc.md)；历史 V2 合同仍见 [Save V2 架构](docs/storage-v2.md)，整笔生命周期见 [草稿安全](docs/draft-safety.md)。

第二轮转向调校使用规则版本 2：中高速转弯能力增强，方向起效和回正更快。已保存的赛道、声音偏好及版本 1 成绩继续保留，V3 当前 HUD 按新几何身份与规则版本 2 的新纪录统计，旧版本圈速完整保留在历史区域。

## 无头浏览器验证

保持开发服务器运行，在另一个终端执行：

```bash
npm run test:browser
npm run test:sound
npm run test:menu
npm run test:handling
npm run test:editor
npm run test:draft
npm run test:storage
npm run test:hud
npm run test:local-game
npm run test:trackbook
```

首次运行若缺少测试浏览器，先执行 `npx playwright install chromium`。脚本使用 `headless: true` 启动 Playwright 自带的独立 Chromium，不使用日常 Chrome。不连接已有浏览器、不使用系统级输入、不打开测试报告。所有键盘和鼠标操作都只发送给无头测试页面，并忽略继承的 `PWDEBUG` 环境设置。

也可通过 `PAPERLAP_URL=http://127.0.0.1:4173 npm run test:browser` 验证生产预览。测试会修改自己的隔离浏览器上下文中的存档，不接触日常浏览器数据。自动化截图写入 `test-results/screenshots/`，结果写入 `test-results/browser-report.json`；`docs/screenshots/` 保留交付时选取的截图。

`test:menu` 检查 ready/running/paused 的 Esc、Space 快捷暂停、菜单/说明/赛道本/编辑返回链、草稿放弃确认、原生按钮、重复键、失焦与存储/场景异常，以及三种桌面尺寸和 reduced-motion。报告及截图在 `test-results/menu/`。

`test:focus` 单独检查鼠标、键盘与混合输入的非封闭式焦点、说明/草稿返回、赛道选中分离、三种桌面尺寸和 forced-colors/reduced-motion，保存修后截图及主流程无头录屏到 `test-results/focus-review/`。

`test:motion` 覆盖菜单/编辑纸页、两种意图、快速路由、输入方式焦点、失败不庆祝、三尺寸、初始/运行中 reduced-motion、真实有效圈，并在正常/4× CPU 下测量事件处理完成延迟和 rAF 节奏。`PAPERLAP_URL=http://127.0.0.1:4175 npm run record:motion` 同时录制六段实际 WebM，生成 `test-results/motion/review.html`（手动打开观看，不自动播放/打开）。关键帧与 JSON 报告也在该目录；录制需先运行构建预览，见 [动效验证](docs/game-motion.md)。

`test:sound` 用真实页面鼠标和键盘验证驾驶中开关声音时计时、车辆、音频增益、持久化与输入保持正常，检查 ready/paused 下 Tab、Enter、Space 的原生行为，并投递窗口/标签生命周期事件验证安全暂停。报告保存在 `test-results/sound/report.json`；不切换系统前台应用。

`test:handling` 检查真实方向输入、连续两圈较快驾驶、急弯前松油以及旧成绩迁移，结果为 `test-results/handling-report.json`，截图为 `test-results/handling-v2.png`。

驾驶输入的等待按只读遥测中的模拟时间判断，避免不同无头渲染速度造成误报；完整圈脚本保留有界的墙钟超时。R 重置通过真实键盘事件后立即采样，验证计时归零，不向游戏写入车辆或计时状态。

`test:editor` 用真实指针绘制接近报错截图的路线和带手抖的路线，检查闭合提示、R/Enter/Esc、输入焦点、拖画中断恢复和三种桌面尺寸。报告与截图保存在 `test-results/editor/`。

`test:storage` 检查真实 localStorage 的 V1/V2→V3 迁移、全部旧纪录历史与原文字节、当前 PB 隔离、WebCrypto 摘要、整圈改线/改名/刷新、真实第二标签锁、旧客户端冲突、损坏/未知 V3、配额失败重试、受限存储驾驶及旧/新整笔草稿归属。报告与三尺寸截图保存在 `test-results/storage/`，本轮实测见 [Save V3 验证](docs/save-v3-verification.md)。

`test:local-game` 检查正式游戏中的真实两弯调整、非法拒绝、撤销重做、保存刷新/新纪录、菜单返回、局部恢复与中断、旧键原文、错误归属、quota/清理失败、只读锁、外部冲突和场景异常；同时生成三尺寸截图与实际 WebM。`bench:local-game` 在正式游戏测 200/450/900 点、正常与 4× CPU 的事件、预览、松手、采用/保存、纹理与重复开关资源；结果在 `test-results/local-game/`，不自动打开浏览器或报告。

`test:hud` 用真实 DOM 边界、文本范围和页面命中检查三桌面尺寸的计时卡片居中、顶部不重叠、计时/PB/历史完整可见，以及历史面板返回后的键盘焦点与布局；覆盖空存档、旧纪录、当前 PB、长名称及配额错误。截图与 48 次布局测量保存在 `test-results/hud-review/`。

`test:trackbook` 从真实鼠标新建 B 开始，检查 A/B 切换与刷新恢复、车辆/圈速/HUD/输入/声音同步、改名、编辑取消、删除确认、容量上限、配额与存储拒绝下的失败重试，以及三种桌面尺寸与键盘焦点。还检查长/短赛道名、新建/编辑意图、暂停和通知的道路/车辆遮挡，并通过真实键盘有效圈触发新纪录截图。P1-03 扩展检查 T/E/N/Space/R、分层 Esc、输入/IME/组合键、原生按钮激活、真实 SVG 与成绩、20 条内部滚动、失败不闪成功、动画中断与 reduced motion。报告与截图保存在 `test-results/trackbook/`，`drawer-*.png`、`switch-ready-*.png` 为 P1-03 抽屉与切换验收画面，`ux-*.png` 保留名称、绘图和通知回归。

`npm test` 同时覆盖缓存突变安全和 20 条赛道、每条 350/900 点的性能回归。`npm run bench:storage` 可输出操作耗时；与原 PR 版本比较、测量真实 localStorage 的命令及结果见 [存档性能复核](docs/storage-performance.md)。未变化几何通过完整坐标快照安全复用，外部存档和变更路线仍严格验证。

## 首版限制

PC 键盘优先，未提供手机触控驾驶；赛道本提供本地最多 20 条路线的纸片抽屉、缩略图和键盘导航。提供保存后中心线的局部弯道调整，不支持自由贝塞尔控制点或交叉道路。V1 孤立成绩缺少路线数据，暂只能归档；存档没有跨标签页合并协议，建议只在一个标签页游戏。几何校验对小半径和紧邻路段较保守，失败时把圈画大、把弯画圆即可。赛车采用简化惯性模型；没有倒车、实体障碍碰撞和幽灵车。声音是轻量合成音，自动化检查开关、保存和切换后引擎静音，听感需人工判断。

## 局部弯道预研原型（P1-05B-01）

独立演示，不在正式游戏菜单中开放，也不会保存路线、纪录或整笔草稿：

```bash
npm run demo:local-edit
# 手动打开 http://127.0.0.1:5174/prototypes/local-edit.html
```

在道路上按住左键拖动，黄色范围是本次影响区，虚线是初始路线。松手后严格检查，合法时可按 Enter 或点“采用到演示”；Ctrl/Cmd+Z 撤销，Ctrl/Cmd+Shift+Z 重做。Esc 先取消当前拖动/预览，空闲时取消全部；R 回到原路线。起点及闭合接头受保护。刷新会丢失演示调整。

“读取此站赛道（只读）”只读取同 origin 的有效 Save V2/V3；端口不同读不到正式赛道时可继续用四种样例。也可在运行正式开发服务的相同网址下手动访问 `/prototypes/local-edit.html`，读取该网址的已有赛道进行内存实验。默认生产构建不包含原型；独立构建使用 `npm run build:local-edit`，输出到 `dist-prototype/`。

`npm run test:local-edit` 用隔离无头浏览器重新生成三尺寸截图、真实操作录像及浏览器性能/资源报告；`npm run record:local-edit` 增加对比画面停留，便于审查录屏；`npm run bench:local-edit` 测纯算法的 200/450/900 点性能。两者输出到 `test-results/local-edit/`，不自动打开浏览器或报告。算法、纪录身份与后续草稿协议提案见 [RFC](docs/local-edit-rfc.md)，测量方法与实际结果见 [原型验证](docs/local-edit-verification.md)。
