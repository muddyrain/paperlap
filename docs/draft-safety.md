# P1-05A 草稿生命周期与撤销恢复

V3 接入补充：正式游戏现在使用 `paperlap.draft.v2` / schemaVersion 2，整笔快照/历史不变，来源额外绑定 geometryIdentity 与 geometryDigest。通过策略适配读取正式 V3；原 draft.v1 保留只读，不能仅凭旧 UID/指纹恢复。只读/损坏正式来源时仅保留内存绘制并显示未备份，仍可明确确认放弃内存稿退出。`DraftStorage` 默认参数继续保留旧 V1 协议供兼容测试，实际游戏传入 V3 策略。详见 [Save V3 RFC](save-v3-rfc.md)。

基线：master `4eb52c81`。草稿是整次单笔绘制状态，不是逐点编辑历史。

## 状态与操作

| 操作                              | 内存状态                                 | 独立 checkpoint                            | 正式赛道       |
| --------------------------------- | ---------------------------------------- | ------------------------------------------ | -------------- |
| 进入新建 / 编辑                   | 空笔迹；询问匹配草稿                     | 只读，不自动采用                           | 不变           |
| 完成一笔（有效或无效）            | 加入有界历史，重新几何校验               | 保存 raw、overflow、完成标记               | 不变           |
| 绘制中 / 明确中断                 | 低频保留；中断结束手势                   | 标为 interrupted；不能恢复 pointer capture | 不变           |
| R 重画 / 撤销 / 重做              | 整次快照切换                             | 空状态仍保留最近一份非空快照供撤销         | 不变           |
| 继续上次绘制                      | 重建预览和校验结果；空稿可撤销至保留笔迹 | 不写 Save V2                               | 不变           |
| 暂不处理 / Esc 关闭恢复提示       | 回原入口，不采用、不清理                 | 保留                                       | 不变           |
| 确认放弃                          | 已确认的对应备份先可靠清理，再退出       | 清理失败时留在编辑器，明确提示             | 不变           |
| 正式保存失败 / replace 仅临时试玩 | 保持既有 Trackbook 语义                  | 保留                                       | 由既有事务处理 |
| 正式写入且场景提交成功            | 退出编辑                                 | 清理对应草稿；清理失败明确提示             | 由既有事务处理 |

## 数据与失败策略

- `paperlap.draft.v1`，schemaVersion 1；不修改 Save V2 / V1、几何、物理或圈速。
- 来源包含 create/replace、源 UID、原几何指纹。恢复要求意图、UID、指纹全部匹配；原条目删除、换 UID 或原路线变化后拒绝旧归属，保留原文，不自动清除。其他条目的变化不影响本条目的草稿。更换存档后按既有 UID/几何身份判断，不新增 Save V2 实例 ID。
- 单次历史最多 24 次撤销；刷新只恢复当前状态和一份完整保留笔迹，不持久化完整撤销栈；单次笔迹不超过 ROAD.maxRaw；最多 12 个持久草稿，整体不超过 600,000 字符。有限坐标有边界；不存 PNG/candidate，恢复复用 fromDrawing。
- 绘制中最多每秒 checkpoint 一次，完成/中断/撤销等离散操作立即 checkpoint；无动画回调触发任何数据动作。
- 损坏/未知版本不覆盖。容量或权限失败不妨碍画图，持续显示未备份状态。
- 初始读取/归属检查未建立可靠会话时，Esc 确认页明确提供“仅放弃本次绘制”，说明旧备份不会删除。用户确认后仅退出内存稿，不尝试 setItem/removeItem。已确认会话的后续清理失败仍留在编辑器，不静默跳过。
- A 完成 → R → B 尚未结束时，周期采样、pagehide、blur、resize 和 pointercancel 均同时保留 interrupted B 与完整 A；恢复后撤销一次找回 A。A 的安全副本独立于 24 层历史淘汰，直到新的整笔真正结束（完成笔迹可以几何无效），或用户明确放弃；不增加版本键和持久槽位。
- 写入/删除前比较本会话读到的原始草稿和正式存档字符串；其他标签发生变更时拒绝写入并保留双方原文，不自动合并。
- 不承诺恢复浏览器已丢失的手势：中断稿可查看、保留、撤销或重画，不能直接当有效赛道保存。
- Ctrl/Cmd+Z 撤销、Ctrl/Cmd+Shift+Z 重做仅在编辑器非输入框中生效；忽略 IME、重复键及 Alt。键帽按平台显示，保留原生按钮 Enter/Space。

## 验收计划

纯数据/存储测试覆盖历史边界、深拷贝、重建验证、归属、损坏/超限、并发冲突、写入/清理拒绝。真实无头浏览器覆盖 R/撤销/重做、有效/无效刷新恢复、中断、create/replace 与 A/B 归属、正式保存失败与成功、放弃与暂不处理、输入框/IME/重按、快速动效切换及三种桌面尺寸。所有既有浏览器套件按 Issue #11 回归。

## 实现分工与复现

- `draft.ts`：整笔快照、历史边界、来源匹配和复用几何校验的状态重建。
- `draft-storage.ts`：独立版本、严格解析与上限、精确字符串比较的乐观冲突检查；不写正式存档。
- `draft-ui.ts`：备份状态、恢复弹窗、撤销按钮、焦点与快捷键键帽；复用既有纸片动效。
- `TrackEditor` 仅在离散动作或低频采样时通知 checkpoint。`GameMenu` 在放弃清理失败时保留编辑状态，暂不处理沿既有返回链退出。
- 正式原文身份查询通过 `storage.ts/readTrackFingerprint` 复用既有逐存储的精确字符串校验缓存；仅已由 loadSave/writeSave/完整 parseSave 验证且字节未变时省略重复几何校验。返回只读指纹，不缓存或信任可变 Save。新存储对象、外部变更、非法路线/元数据/成绩仍完整严格校验，正式 writeSave 的校验顺序不变。
- `main.ts` 仅接线：进入草稿来源、页面退出 checkpoint、编辑器专用组合键、正式事务成功后的清理。

```bash
npm run build
npm run preview -- --port 4185 --strictPort
# 另一终端；浏览器始终为独立 headless Chromium
PAPERLAP_URL=http://127.0.0.1:4185 npm run test:draft
```

输出：`test-results/draft/report.json`、三尺寸 PNG、`undo-redraw.webm` / `refresh-recovery.webm` / `discard-safety.webm`。录像由测试页面自动录制，保留真实鼠标绘图和键盘操作，不录制用户桌面。验收结果与交付截图见 [验证记录](verification.md)。

Review 专项：`PAPERLAP_URL=http://127.0.0.1:4185 npm run test:draft-review`（4 项读取/确认退出 + 5 项 A/B 中断恢复）。近容量性能：`PAPERLAP_URL=http://127.0.0.1:4185 npm run bench:draft:browser`，使用 20×900 点真实隔离存档和鼠标点击，分别测量既有验证热路径与外部有效原文变更后的完整验证路径。
