# Save V2：PR #2 几何验证性能复核

对应 [评审意见](https://github.com/muddyrain/paperlap/pull/2#discussion_r4377916153)。验证日期：2026-10-26。原实现基线为 `93165ce`，优化版本保持 Save V2 结构、V1 迁移和成绩键规则不变。

## 测量方法

两组存档均包含 **20 条不同 UID、不同几何的有效椭圆路线**，每条分别为 350 / 900 个点。使用真实 `save.ts`、`storage.ts`、`geometry.ts` 和 `config.ts`；基线源码通过 `git show 93165ce:...` 写入被忽略的测试目录并直接执行，没有使用近似算法代替验证。每个操作先预热一次，再采样 5 次；表中为中位数，单位 ms。准备数据、模块加载和首次加载在热操作测量之外。

环境：Windows x64，Intel Core i5-12400F，Node.js 26.4.0 / V8 14.6.202.34-node.21；浏览器为独立无头 Chromium 141.0.7390.37。浏览器通过本地 Vite 服务加载测试模块，在没有 Phaser 渲染负载的专用页面上测量真实、隔离的 `localStorage` 同步 API 开销；每种版本使用独立上下文，写入后重新加载确认 20 条赛道仍存在。所有浏览器及上下文正常关闭，控制台错误为 0。

## 安全边界与回归

- 每次复制当前坐标并逐点比较完整数值、顺序、点数和道路宽度；私有快照不暴露给调用方。不以可变对象身份、UID 或量化后的几何指纹单独作为信任依据。
- 全新 JSON 的点数组没有已验证快照，必须完整验证。新增、替换路线和 V1 迁移显式执行完整几何验证；改变缓存对象的任一坐标同样触发重新验证。其余已验证且未变化的路线复用结果。
- 每次仍校验存档结构、UID 唯一性、活动条目、版本、名称、成绩归属/数值、容量和序列化长度；调用方仍可修改自己的 Track，不改变现有可变 API。
- `writeSave` 每次调用 `getItem`。仅当原文与该存储对象最近已完整验证或成功写入的字符串完全一致时复用验证；另一个标签页/开发工具改动原文会触发完整解析。缓存不保存可变 Save 对象，写入失败不记录新的已保存原文。
- 新增 8 项安全回归，覆盖验证后突变、冻结数组内可变点、稀疏数组、同指纹精细坐标修改、元数据/成绩篡改、新增/替换错误路线、外部存储篡改、不同存储对象与配额失败。原有 V1 保留和全部成绩归属测试继续运行。
- 新增两组性能回归（20×350、20×900）。六种热操作的中位数必须低于同一组不可信 JSON 完整解析中位数的一半，避免依赖固定机器毫秒阈值；两组在基线上均先复现失败，优化后通过。

缓存只消除重复的 O(点数²) 验证，热操作仍包含 O(总点数) 的安全比对/复制及序列化。快照使用 WeakMap，不强持有已被丢弃的输入/输出数组；原文缓存每个存储对象只保留一份字符串。现有指纹仍采用 0.1 坐标量化与 32 位哈希，极小编辑可能保持原 ID，这条非阻塞评审提示留给后续几何身份设计；本轮缓存不会将同指纹的不同坐标误认为未修改。
