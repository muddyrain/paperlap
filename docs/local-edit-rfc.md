# P1-05B-01：局部弯道调整 RFC

状态：原型已完成技术验证，等待 Code Review 与用户试玩。基线 master `dacaa693`，对应 Issue #12。只交付独立演示，不向正式游戏添加入口，不写正式存档、纪录或整笔草稿。

## 要回答的问题

已经保存的路线只有离散中心线，没有原始贝塞尔手柄。能否直接推拉一小段弯道，同时让其他道路逐点不变、起点与方向不动，并保留直觉清楚的取消和撤销？本轮先验证有限弧长位移，再决定是否值得正式集成；不承诺所有拖动都合法。

## 算法选择

| 方案                              | 局部性与平顺性                                                         | 成本与手感                                                                      | 历史兼容及风险                                                                        |
| --------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| A：中心线有限支撑位移（本轮原型） | 保留点序和数量；支撑范围外数值完全不变；权重在边界的一、二阶导数均为零 | 按道路弧长选区，不用圆形空间刷子；每帧 O(n)，选中位置跟随拖动，调整半径决定软硬 | 直接接受 Track.points，不重建整圈；大位移会挤压采样、形成急弯或交叉，必须松手严格验证 |
| B：派生稀疏锚点＋局部受限插值     | 可固定区间外采样及端点切线；必须限定插值区间，不能全圈拟合             | 锚点少、编辑次数少；但鼠标选点与真实弯心可能错位，自动布点密度影响手感          | 原始手柄已丢失，拟合可能先改变旧路线；必须保留原点且局部重建，新旧采样对应更复杂      |

优先 A，因为它不需要假定旧路线来自某种曲线，也不需要预先“美化”用户作品。B 暂留为对照设计，不加入另一套工具箱；如果试玩发现 A 的宽弯拖动不自然，再做同基线的 B 实验，不能根据测试通过率断言 A 手感已获认可。

### A 的具体定义

1. 一次拖动开始时冻结当前已采用中心线，计算累积弧长 `s[i]` 和总长 `L`；鼠标投影到最近线段得到弧长 `c`。选点是沿道路距离，不影响空间上很近、弧长上很远的另一条道路。
2. 请求半径 120–320 世界单位。起点两侧至少保护 64 弧长，并完整保护首尾相邻线段（兼容稀疏采样）；`gL = max(64, s[1])`、`gR = min(L-64, s[n-1])`，有效半径 `r = min(requested, c-gL, gR-c)`。不足 80 时拒绝选点并说明原因。影响区不会跨越闭合接头，也不会移动首尾相邻线段；起点位置、方向和道路宽度保持。该保护区是本轮明确限制，未来若需编辑起点附近，应单独设计固定位置/切线约束，不能直接绕过保护。
3. 对 `q = abs(s[i] - c) / r < 1`，权重 `w = (1 - q²)³`；否则 `w = 0`。候选 `p'[i] = p[i] + w * delta`。黄色范围包含所有移动顶点及其两侧相邻线段，端标记落在未移动的外侧顶点；线性连接会有最多一个采样段的外扩，不将仅按顶点权重的范围误报为整段道路边界。权重在支撑边界值、一阶、二阶导数为零，连续的位移场不会在边缘附加折角；离散道路是否足够平顺仍由已有 validate 判断。位移向量限制到 360 世界单位，拒绝非有限参数。不运行全圈 smooth/resample/fromDrawing。锚点是线段投影、不插入新点；稀疏采样时峰值位移可能略小于鼠标位移，需通过试玩判断跟随感，不能以理论平滑性代替体验验收。
4. 每帧至多消费最后一个 pointermove，计算与画图；仅做有限数值/越界轻提示，明确标“尚未校验”。松手同步调用一次原 validate；显示原错误位置与中文原因。合法候选仍需点击“采用到演示”或 Enter 才进入内存历史；非法不能采用。采用复用该不可变候选的验证结果，不额外全量计算。
5. 每次拖动相对于当次冻结基线计算，不能把上一帧结果累加，避免鼠标事件频率改变结果。多次采用后，局部性以当次拖动前的路线为准，初始路线始终保留为淡色对照。

### B 的可实现对照设计

从原中心线按弧长每约 120–200 单位派生锚点（密弯可加密），保存原点序到锚点区间的映射。拖动某锚点时，只开放它两侧的有限区间；区间外端位置与原路线切线固定，内部用分段 cubic Hermite 重算。不能把拟合结果直接替换原路线，否则即使鼠标没动也可能先“修形”。可用 `Pnew(s) = Pold(s) + Hnew(s) - Hold(s)` 只施加插值差值，保证零拖动恒等；边界差值和切线差值为零时有 C1 衔接，若要 C2 需额外的二阶端约束/五次插值。

初始派生/映射 O(n)，每次更新 O(m)（区间内采样数），但锚点布置、端切线估计、短区间过冲都多出参数。改动仍需完整 validate；拟合与点密度不能作为合法性证据。它可提供“弯心/弯口”明确手柄，却不必然比直接抓道路更直觉。A 的起点保护、精确原点对照和未来 identity/草稿约束同样适用于 B。本轮不实现 B 的拟合器，避免在没有 A 试玩结论时扩成完整控制点编辑器。

## 数据与交互

纯模块不接触 DOM/Storage/Phaser。拖动会话保存冻结 points、投影锚点、有效半径、逐点权重；输出独立候选数组，不突变传入 Track。演示页保存 original、accepted、pending、drag 和最多 24 次整条中心线历史；整个页关闭即丢失。

演示状态：空闲 → 选区拖动（未验证）→ 合法/非法候选 → 采用/取消。合法候选采用后才推进历史。非法候选保留红色预览和错误点，已采用路线仍在；可取消并重新选区。撤销/重做恢复精确点值，不重新平滑。Esc 优先取消当前拖动/候选，空闲时取消全部调整回 original；R 还原原路线。Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z 只在非输入控件中处理，不劫持原生按钮 Enter/Space。选中、影响区、原始虚线、当前路线、保护区和非法位置有文字图例，颜色不是唯一信息。

pointercancel、lostpointercapture、blur、visibilitychange、resize 均取消当前未采用手势并释放捕获，保留已采用历史；不把中断当作合法完成。重复拖动会丢弃未采用候选，以已采用路线重新建立会话。页面不依赖动画完成回调，reduced-motion 下交互完全一致。

独立入口 `/prototypes/local-edit.html`，通过项目 Vite 启动，复用真实 geometry/Save 解析，避免复制校验器。独立构建输出到 dist-prototype，默认游戏构建仍只有 index.html；正式 main.ts、菜单和编辑器不引用原型。默认加载合法演示 Track.points（宽环、连续 S 弯、较紧弯、靠边弯），可显式只读加载同 origin 的已保存 V2；没有读取权限时仍可玩样例。不读取/写入 P1-05A 草稿，不提供写盘接口。

## 纪录身份风险与兼容提案（本轮不实现）

现 fingerprint 将坐标四舍五入到 0.1，再执行 32 位 FNV 风格哈希。小于量化边界的坐标变化可以保持同 ID，即使实际点不同；32 位还只有有限取值，不能作几何相等证明。确定性测试应展示两份合法且点不同的路线仍产生相同 ID 和 recordKey。此问题不能靠改变 RULES_VERSION 掩盖，也不能本轮偷偷替换 hash。

| 方案                            | 优点                                         | 边界                                                                           |
| ------------------------------- | -------------------------------------------- | ------------------------------------------------------------------------------ |
| 更强 digest                     | 比 32 位抗碰撞，能检查草稿基线和内容完整性   | 必须版本化规范化数据；仍不能将摘要当作业务修订历史，异步 digest 需要防过期结果 |
| 独立 geometry identity/revision | 一次可靠采用建立独立身份，不会因微调沿用成绩 | 必须和正式写入事务一致；撤销/复制/导入都需明确语义                             |
| 只升级 recordKey 版本           | 将旧成绩与新规则隔离                         | 仍需可靠几何身份，单独加前缀不能解决碰撞                                       |

推荐下一阶段：Save V3 的 `geometryIdentity`（独立 UUID 修订身份）＋版本化 SHA-256 canonical digest，记录键为 `UID + geometryIdentity + RULES_VERSION`。canonical 数据含版本、道路宽度、按原点序的有限 IEEE-754 数值（规范 -0），不旋转/反转/简化/0.1 量化，因为点序起点与驾驶方向有语义；实现需指定确定性编码及测试向量。digest 用于比对，identity 用于纪录归属；全量点比对决定是否真无变化。改名不换身份，新几何采用换身份；复制赛道换 UID，不能共享 best。精确 Undo 回可信已知修订可复用该修订身份与对应成绩；否则建立新身份，不依据旧 32 位 ID 自动复用。

迁移草图：新键写 V3 且验证成功后才启用，原 V2/V1 字节保留，禁止双写伪装兼容。保留 UID、活动条目、声音和所有旧纪录。仅有旧 32 位键无法反证历史微调，所以旧 best 作为关联当前条目的 legacy-best 明确保留/显示，不冒充新 identity 的可信成绩；不匹配的历史成绩只归档。规则版本不变；物理规则变化时才按独立规则版本处理。失败回原 V2，旧客户端回滚可读保留 V2，但回滚后不承诺看到 V3 新作，需明确提示并禁止静默覆盖。容量和大小在迁移前预检，不自动裁剪；具体 V3 schema、legacy 展示、跨标签升级与回滚 UX 必须单独 Review。

## P1-05A 草稿兼容与未来失败保护

不要把局部 operations 塞进 raw。建议独立 `paperlap.local-draft.v1`（协议草图），来源包含 intent、baseUid、baseGeometryIdentity、baseDigest、算法版本；保留基线引用、合法候选精确快照和有限操作日志 `{centerArc,radius,delta}`。日志用于解释与撤销，恢复以有界精确快照为准，不能依赖未来算法重新播放得到相同浮点结果。原 draft.v1 保持整笔含义和原文，不混用/自动转成局部稿。

恢复先匹配 identity/digest 和正式原文，再严格验证候选，明确“继续局部调整 / 放弃 / 暂不处理”，不自动保存/起跑。未完成新拖动保留最近合法候选；异常采样不覆盖它。正式提交沿 Trackbook 的准备→可靠写入→场景提交顺序，任一步失败保留对应草稿；只有可靠写入且场景成功或明确放弃后清理。首次读失败的内存放弃与已确认备份清理失败继续区分。多标签使用精确原文乐观冲突检查，未知版本/损坏/权限/配额失败保留原文并说明限制。草稿限额、历史上限和协议迁移在 02 单独评估，不能无限保存多份 900 点快照。

## 原型实测结论

保留方案 A：200/450/900 点的真实鼠标预览均只更新有限支撑区，范围外点数值完全不变；支持合法/非法预览和精确撤销。900 点浏览器预览中位 0.30ms、P95 0.40ms，松手完整校验中位 29.6ms、最大 35.3ms，不能把完整检查放进 move。50 次连续拖动与 11 次重开未观察到本负载下资源持续增长。默认游戏构建与 dacaa693 逐文件 SHA-256 完全一致。

同时确认限制：稀疏采样必须保护首尾整个线段；仅 64 弧长的顶点冻结不足以保证首段方向不动，因此原型采用 gL/gR 的完整线段保护。原有规则会拒绝部分稀疏折线，大拖动也可能非法，不做全圈再平滑来掩盖问题。旧 hash 的 0.001 微调反例已通过测试，独立几何身份必须先于正式保存集成。

这只验证可行性，尚未获得玩家手感验收。B 保留为未来需要时的实验备选。完整操作、机器环境、测量范围、三组原/新/非法截图和录屏复现见 [验证记录](local-edit-verification.md)。下一步先试玩本 PR，再决定 P1-05B-02。

## 正式集成 P1-05B-02B

在 master `347d2eb3` 的 Save V3 基础上，正式游戏增加独立 L 入口，E 保持整圈重画。复用本 RFC 的 `prepareLocalDrag/deformLocal/LocalEditModel`，不改变变形公式、保护区或既有几何校验；原型本身仍只读，不提供正式写盘。

实际状态/返回图、严格 Trackbook 局部事务、`paperlap.local-draft.v1` 精确快照协议与失败矩阵见 [集成合同](local-editor-integration.md)。采用只是编辑历史，Ctrl/Cmd+Enter 才保存；新 UID 不创建，实际改线由既有 V3 创建新几何身份，旧成绩保留，不恢复旧身份冒充 PB。源 UID/身份/摘要/算法不一致的草稿保留原文，刷新只恢复相邻历史，不重放浮点 delta。
