# P1-02：赛道管理状态与失败恢复

对应 [Issue #3](https://github.com/muddyrain/paperlap/issues/3)，基线为 P1-01 `6356036d`。复用 Save V2 操作、存储保护和几何缓存；不改驾驶、圈速或路线规则。

P1-05A 的绘制草稿另存独立版本键；本页“不写盘”指不写正式 Save V2。预览、重画、撤销与明确取消会按 [草稿生命周期](draft-safety.md) 备份或清理，不改变下述正式事务顺序。

## 状态转换

| 操作           | 持久化与场景行为                                                                   | 完成状态                            |
| -------------- | ---------------------------------------------------------------------------------- | ----------------------------------- |
| 新建           | 进入独立 create 草稿；有效路线经 addTrack 分配新 UID；准备场景资源，保存成功才采用 | ready，等待明确开始                 |
| 编辑当前       | replace 草稿沿用活动 UID、名称和历史纪录；有效路线采用后仍按原行为试跑             | running；保存失败明确提示未保存     |
| 取消任一草稿   | 不写盘、不新增条目；恢复进入编辑前的路线、车、圈速、越界状态                       | 原来 ready 则 ready，否则 paused    |
| 切换           | 先停止输入、计时与声音；准备目标资源；保存活动 UID 成功才更新场景/HUD              | ready，车回起点，本圈/越界/特效清空 |
| 重选活动条目   | 无写盘、无场景重建                                                                 | 保持原状态                          |
| 改名           | 校验非空、40 码元上限；保存成功才更新列表                                          | UID、路线、成绩及游戏状态保留       |
| 删除非活动条目 | 明确确认后保存；只移除目标 UID 及其纪录                                            | 活动场景不重建                      |
| 删除活动条目   | 明确确认后按 Save V2 选择剩余第一条；与切换相同                                    | ready；最后一条拒绝删除             |

编辑时禁用管理命令；管理对话框内的键盘输入不传给驾驶或编辑器。打开管理入口不直接暂停，焦点离开驾驶区仍遵循既有自动暂停规则。

新建采用后焦点留在游戏区域；即使玩家一直按住 Enter 保存，也不会由重复键事件触发“开始试跑”。新建的按钮、绘制提示和无障碍标签均明确写“保存”，编辑当前则沿用“试跑”。

## 提交与失败

控制层统一执行「纯函数计算候选 → 停止旧驾驶（仅需换场景时）→ 准备派生数据及画布资源 → writeSave → 提交 Save 与场景」。元数据操作不准备场景。候选非法、配额不足、存储拒绝、损坏原文或容量上限均返回具体错误；严格管理操作不提交候选。切换失败可以安全暂停，但旧车辆、计时、活动条目、HUD 与存档仍保留；新建失败保留有效草稿，可重试或取消。预览、重画及取消均不写盘。

场景准备失败发生在写盘之前，旧 Save 保留。极少见的写盘后场景提交异常无法假设回写旧存档一定成功，因此采用已保存候选为权威，停止所有操作、静音、隐藏游戏画面并显示重新加载按钮。若是未保存编辑的场景提交异常，则撤回内存候选。重新加载均从持久化 Save 重建，避免继续操作半提交画面。此状态不显示成功消息。

原有编辑、静音和最佳成绩的「存储受限仍可继续本次试玩」语义保留，提示本次未保存。名称为空的历史条目只在 UI 显示“未命名赛道”，不改原文。没有跨标签并发合并协议。

## 验证边界

控制层公开命令及可观察 Save：新建/编辑意图区分、取消、同几何不同 UID、选择稳定性、删除归属与确认、候选提交、存储和渲染失败。持久化使用真实 Save V2 与 writeSave，存储边界注入内存容器及故障。

`test:trackbook` 使用隔离无头 Chromium，通过 UI 和真实键鼠绘制、切换、改名、确认/取消删除、刷新与故障重试；只读遥测检查车辆、圈速、场景、输入、声音和活动 UID。覆盖 1366×768、1280×800、900×700 控件边界。报告保存在 `test-results/trackbook/`。
