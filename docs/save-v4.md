# Save V4：大纸面与既有作品兼容

当前运行版本使用独立 **`paperlap.save.v4`**，通过 `storage-v4.ts` 读写。V3/V4 共用 `save-modern.ts` 与 `storage-modern.ts` 的身份校验和事务核心；旧 `save-v3.ts` / `storage-v3.ts` 入口仍只接受 V3 与旧尺寸赛道，保留兼容测试。

## 地图与身份

- Track schema 1 保留原 `1440×860` 世界和原道路边界，已有作品不自动放大。
- Track schema 2 使用独立 `5760×3440` 纸面，道路宽度仍为 108。`WORLD` 是旧纸面与界面参考，`MAP` 独立于视口；平移缩放不改变路线点、道路宽度或车辆尺度。
- 默认 `validate` / `fromDrawing` 仍验证 schema 1；大地图显式传空间版本 2。正式点数仍最多 900，原始绘图最多 1600 点。
- `trackBounds` 供驾驶边界使用，`drawingBounds` 供道路中心线编辑边界使用。道路不再受屏幕 HUD 留白限制。
- V4 保留 UID、几何身份、纯几何摘要和规则版本的成绩归属，`RULES_VERSION` 仍为 **2**。schema 变化属于新修订，即使点与宽度相同，也不能重绑既有身份。
- 3D 渲染和追车镜头不改变已保存几何及驾驶规则，不单独触发 PB 清空。实际改线生成新身份，旧成绩保留在历史中。

## 正式存档升级

| 来源 | V4 行为 |
| --- | --- |
| 无旧存档 | 新建“长纸环游”样例，保存为 V4 |
| 合法 V3 | 保持作品、名称、尺寸、UID、几何身份、摘要、PB 与历史，不替换当前作品 |
| 合法 V2 / V1 | 沿用严格迁移和旧成绩归档规则，直接写 V4，不创建中间 V3 |
| 已有 V4 | 完整验证后加载，并核对 V1/V2/V3 来源摘要 |
| 损坏、未知或来源冲突 | 保留原文、停止写入，提供临时试玩与导出入口 |

V1、V2、V3 原始键不自动改写或删除。`legacySources` 保存 V1/V2/V3 原文摘要；迁入 V3 的旧来源摘要也必须与当前 V1/V2 字节一致，升级不能消除已有分支冲突。

已有玩家可从赛道本的“体验长赛道”新增独立样例，原作品保留。这是普通的作品新增事务，受数量上限与写入许可约束。新建、重绘或局部修改保存成功后均回到等待开始状态。

## 草稿分离与恢复

| 用途 | 当前键 | 结构与来源 |
| --- | --- | --- |
| 分段绘图 | `paperlap.draft.v3` | schema 3；记录分段端点、已完成路线、空间版本及作品/几何/绘制意图 |
| 局部调整 | `paperlap.local-draft.v2` | schema 2；绑定 UID、几何身份、摘要、空间版本与局部算法 |

### 分段草稿

开放路线是可继续的草稿。每段结束、撤销、重做等离散操作备份已完成段和续画位置；恢复后从末端继续。未完成手势中断时保留已完成段。正式保存并提交场景成功后，或明确放弃时，才清理对应草稿。

旧 `paperlap.draft.v1` 和 `paperlap.draft.v2` 原文字节保留，界面提供旧草稿提示，不自动转换或套用到分段绘图。当前分段草稿最多 12 份 / 600,000 字符，不自动淘汰；只读、来源不匹配或可靠写入失败时明确报告未备份。

### 局部草稿

首次打开 V4 局部调整，若 `local-draft.v2` 不存在，则尝试复制可解析的 `local-draft.v1`。匹配当前作品的几何先严格验证，再写新键；复制前后核对旧草稿字节、正式来源与写入许可，旧原文保留。

V2 的空文档作为已处理标记。即使清理了最后一份草稿，也保留空文档，避免下一次打开又从仍保留的 V1 重复导入。

恢复必须匹配正式作品的空间版本，不能把大地图规则套到旧尺寸作品。当前、前一步和后一步几何均校验；刷新后可恢复最近一步撤销/重做。最多 8 份 / 1,200,000 字符，不自动淘汰。未知或不匹配的旧原文仍可随全部备份导出。

## 写入事务与并发

V3/V4 共用 `paperlap-save-v3-writer` Web Lock，避免两个版本同时持有写入许可。其他标签只读；无 Web Locks 的浏览器只读试玩。

正式写入依次检查许可、来源原文、完整候选、归档不变性与身份不重绑，再可靠写入并读回核对。运行期间和写后复核 V1/V2/V3/V4；旧客户端写 V3、外部写 V4 或来源不一致都会停止保存。刷新重新核对来源，不自动合并。

作品提交顺序为候选 → 场景准备 → 可靠写入 → 场景提交。配额或读回失败不能报告成功，保留旧正式状态和草稿，并释放未采用的 3D 候选资源；资源清理异常不掩盖保存错误。场景提交异常时停止后续操作，要求重新加载可靠写入的状态。

分段和局部草稿各自核对自己的键、正式作品来源及可靠读回。损坏匹配的旧局部草稿不会先被写入新键；失败或只读状态不会假装完成复制、保存或清理。

## 导出与回滚

全部存档导出包含 V1/V2/V3/V4、旧整笔草稿 V1/V2、新分段草稿 V3、旧局部草稿 V1 与新局部草稿 V2 原文。

旧版回滚只看到保留的旧键，不会看到 V4 新作品。旧版期间的改动可能在重新打开新版时触发来源冲突。原始分支与备份应保留，不能靠改摘要把两份不同来源强行当成同一存档。

## 验证入口

- `tests/save-v4.test.ts`：大/旧地图边界、驾驶越过旧屏幕范围、独立 V4 键、V3 身份/PB 保留、旧来源冲突、配额/读回失败、只读和损坏键、V2 直接升级、跨 schema 身份重绑拒绝。
- `tests/local-v4.test.ts`：大图局部保存后的成绩隔离、空间版本匹配、局部草稿复制与清理、防重复导入、旧字节保留、只读/失败/冲突、准备资源释放。
- 分段草稿及视口核心测试覆盖续画、撤销、坐标变换与恢复；`npm test` 顺序运行核心测试。
- `npm run test:next` 依次运行新版本驾驶和编辑的独立无头浏览器流程，支持 `PAPERLAP_URL`，输出 `test-results/next-version/`。

实际运行结果见[本轮验证记录](next-version-verification.md)。原 V3 核心合同保留测试；P1 阶段的浏览器脚本仍有针对旧存档键、整笔编辑与旧布局的断言，不据此宣称当前 V4 全流程通过。
